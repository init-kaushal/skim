## What skim is

A Claude Code plugin (single Go binary + plugin scaffolding) that intercepts likely-expensive `Read`/`Grep`/`Bash` tool calls via `PreToolUse` hooks and substitutes a compact Haiku-produced digest, so bulk content never lands in — or gets re-sent with — the main session's context. It works regardless of which model drives the session (only the worker is pinned to Haiku), reproduces the "Portal by Spotify / shunt" token-saving pattern with no external platform, and fails open (allows the original tool call) on any internal error. Read the spec §1 for the full framing.

## Final review findings and how each was fixed

The final whole-branch review (`docs/superpowers/plans/2026-09-08-skim.md`'s process — see `superpowers:subagent-driven-development`) found:

**Critical (all empirically verified against the real built binary before fixing):**
- **C1** — The Bash deny message told the model to run `skim run -- <original command>`, which still matched the same noisy pattern (`\bcat\s`, `go test`, etc.) and got denied again — infinite escalation, the Bash path never completed. **Fixed:** `BashHook` now allows unconditionally when a command already invokes skim itself.
- **C2** — Both escape hatches (`skim run`, `skim cat` suggestions) told the model to run a bare `skim`, which isn't on `PATH` (the binary lives at `plugin/bin/skim`, invoked via `${CLAUDE_PLUGIN_ROOT}/bin/skim`). **Fixed:** both now resolve and interpolate `os.Executable()`'s absolute path.
- **C3** — `/skim off` / `/skim on` (the README's and `plugin/commands/skim.md`'s advertised primary kill switch) weren't dispatched in `cmd/skim/main.go` — only `skim config off` worked. **Fixed:** added the dispatch case.
- **C4** — `Read` interception had no binary/image gate — a 200KB+ PNG or PDF got denied and up to 400KB of raw binary shipped into a Haiku prompt. **Fixed:** `internal/detect` gained a binary/image detector (extension allowlist + NUL-byte sniff), checked before size-threshold interception.

**Important:**
- **I1/I2** — Grep's sample `rg` call dropped `--glob`/`--type` (described the wrong scope) and ran unconditionally even when the call would pass through (2x rg cost on every single Grep). **Fixed:** shared scope-filter args; sample is now lazy (only computed after confirming the match count exceeds threshold) — required splitting `handler.Deps.CountMatches` into a count-only function plus a lazy `Deps.Sample`.
- **I3** — Grep ignored `output_mode`/`head_limit`, so already-cheap calls (`output_mode: count`, small `head_limit`) got needlessly intercepted. **Fixed:** `hookio.GrepInput` now parses `head_limit`; `GrepHook` passes through for `count`/`files_with_matches` output modes or a small explicit head limit.
- **I4-A** — The worker wasn't actually tool-restricted despite spec §4.4 saying "no tools." **Fixed:** `--tools ""` verified empirically to work (worker replied "NOTOOLS" when asked to run Bash; cached system-prompt tokens dropped from 10446 to 5579).
- **I4-B** — Untrusted digest content (e.g. from an adversarial repo file) reached the main model unlabeled inside `permissionDecisionReason`. **Fixed:** digests are now prefixed with a framing line marking them as data, not instructions.
- **I5** — `skim run -- <cmd>` doesn't use a shell, so a suggested compound command (pipes, `&&`, etc.) got silently re-parsed by the *outer* shell with different meaning; also, wrapping changes what string Claude Code's Bash permission system sees. **Fixed:** commands containing shell metacharacters are now suggested as `skim run -- sh -c '<escaped>'`; README documents the permission-matching caveat.
- **I6** — `metrics.Entry.WorkerTokens` was declared but never populated, so `skim stats` could never show the Haiku-cost side of the ledger — exactly the question spec §9 designates `skim stats` to answer. **Fixed:** `worker.Run`'s signature now also returns token usage parsed from the real `claude -p --output-format json` envelope; threaded through every call site; summed in `Aggregate`; printed by `skim stats`.
- **I7** — `SKIM_ACTIVE`/`SKIM_DISABLED` were checked *after* a config load + full cache-directory sweep on every hook call, not first as spec §4.0 requires. **Fixed:** an early-exit check for these two env vars now runs before anything else in `hookMain`.
- **I8** — No hook timeout declared in `hooks.json`; `worker_timeout_sec` (45s default) was observed borderline. **My original fix instruction (relayed from the reviewer) assumed Claude Code's hook timeout default was ~60s and told the implementer to lower `worker_timeout_sec` to 30. The implementer instead found the real documented default is 600s for command hooks, and empirically showed 30s causes real degrade-open timeouts on a legitimate ~92KB file (30.06s) while 45s left real margin (21.9s–34.8s observed).** They kept the default at 45, added an explicit self-imposed `"timeout": 60` per hook entry in `hooks.json` (tighter than the platform default, for predictability), and kept `Validate()`'s `>55` ceiling binding against that 60s bound. **This deviation was reviewed and accepted as correct** — it's evidence-backed and the premise it corrects was mine, not the implementer's error.

**Promoted from deferred minors (treated as required):**
- **P1** — Added a `Deny` round-trip test with a quote/newline-containing reason (relevant now that C1's fix means deny reasons routinely contain multi-line suggested commands).
- **P2** — Deleted `TestRun_SetsSkimActiveForChild`, which asserted nothing and had a comment describing fake behavior the fake didn't actually have.

### Spaced-path verification (closed)

The one thin spot flagged above — the final one-line Read-hook fix having only unit-test coverage through the injectable `executablePath` seam, never a real binary at a real spaced path — was closed on 2026-09-14 with an end-to-end check against an actual built binary, plus a negative control proving the guard is load-bearing rather than vacuously passing:

1. **Real binary, real spaced path.** `go build -o '<scratch>/skim verify dir/skim' ./cmd/skim`, then drove the real `read-hook` subcommand over stdin against a 9000-line file, with `testdata/fakeclaude` first on `PATH` and an isolated `SKIM_HOME`. The deny reason's escape hatch came back correctly single-quoted: `'…/skim verify dir/skim' cat …/big.go`.
2. **Round-trip through the Bash hook.** That exact suggestion — which contains `cat` and therefore matches the `\bcat\s` noisy pattern — was fed back into `bash-hook`. Result: **allow** (exit 0, empty stdout). `isSkimCommand`'s quoted-prefix fallback recognizes the quoted spaced self-path, so there is no re-deny and no C1 escalation loop.
3. **The suggestion actually executes.** Running it through `sh -c` emitted all 9000 lines, confirming the quoted form is a runnable command and not just a well-formed string.
4. **Negative control.** The same command with the self-path left *unquoted* was fed to `bash-hook` and came back **deny** (`matched /\bcat\s/`) — i.e. without `quoteSelfIfNeeded` this path really does re-open the infinite-escalation bug on a spaced install path. The fix is load-bearing.

Full `go build ./... && go vet ./... && gofmt -l . && go test ./...` green alongside. No code change was needed; this was verification only. With this, every fix wave on the branch has had either an independent review pass or a direct empirical check, so no further scoped reviewer was dispatched.

### Cost-correctness batch (2026-09-14)

A full review of the implementation, with every finding verified against the running binary or the real API, found that the economics were upside-down on exactly the files skim exists for. Four fixes, all measured:

**The framing that was wrong.** The smoke-test datapoint below ("net ~−64,349 tokens") was treated as probably-fine because Haiku is cheaper. It is cheaper, but **Opus 5 input is $5/M, not the $15 that intuition assumes** — so Haiku is only 5x cheaper, against a worker that burned ~3.9x more tokens than it saved. The margin was ~1.3x on Opus, and *negative* on Sonnet 5 and Haiku sessions. Tokens were never the right unit; the fix was to measure dollars.

1. **Worker thinking disabled** (`MAX_THINKING_TOKENS=0` in `worker.Run`'s child env). Producing a structural digest is mechanical extraction, not reasoning. Measured on one 17.5KB file, same prompt and model: **$0.046684 / 31.8s / 4,369 thinking tokens → $0.016165 / 5.7s / 0** — 65% cheaper and 5.6x faster. The digest also came back *more accurate*: with thinking on, the model emitted map ranges running to line 556 of a 411-line file; with it off the last range was 410-420. `--effort low` was tried first and does nothing on Haiku 4.5. This also collapsed the latency/size relationship — wall time is now near-flat at 6–13s from 17KB to 400KB, so `worker_timeout_sec` is no longer the binding constraint it was.

2. **Symbol list capped at 40** (`digest.maxSymbols`, plus the prompt now asks for at most 40). Uncapped, the digest became most of what it was meant to save: a 2,002-line file of 400 near-identical types rendered a ~1,300-token "digest", roughly 1,200 of which was a flat list of every `Widget0…Widget399`. Now 377 tokens on the same file — 3.4x smaller.

3. **Partial coverage is disclosed instead of hidden** (`digest.Coverage`, `worker.Request.Partial`). The Read hook capped its worker input but the prompt still said *"the full contents of the file"* and demanded a map *"top to bottom with no gaps"*. Verified on a 908KB/29,999-line file: the worker saw 46% of it, cut mid-token at `func f13929() { retur`, and the digest disclosed nothing — the model got a structure map ending around line 13,938 believing it covered the file. Now the prompt bounds the model to the excerpt, and the digest leads with an actionable banner: `PARTIAL: this digest covers only lines 1-2000 of 2002 (99% of the file). Lines 2001+ are NOT described below. To see them, Read with offset 2001.` Coverage is derived from the size measurement rather than `len(content)`, so the disclosure is correct on a cache hit too.

4. **Worker input capped by lines, not bytes** (`maxWorkerInputLines = 2000`, byte backstop 128KB, was a flat 400KB). **Claude Code's Read tool returns at most 2000 lines.** Every byte skim read past that was worker cost buying nothing, because the surplus was never going to reach the session's context. Measured against Opus 5 input pricing with the old cap:

   | file | skim | the Read it replaced | |
   |---|---|---|---|
   | 60 KB / 1,933 lines | $0.062 | $0.115 | wins 1.9x |
   | 120 KB / 3,867 lines | $0.096 | $0.118 | wins 1.2x |
   | 200 KB / 6,445 lines | $0.159 | $0.120 | **LOSES 1.3x** |
   | 400 KB / 12,890 lines | $0.311 | $0.119 | **LOSES 2.6x** |

   After: the 400KB case costs **$0.053585** (83% cheaper) and **wins 2.0x on the first read**. `metrics.Entry.OrigTokensEst` was switched to the same 2000-line prefix for consistency — crediting the whole file would book savings for bytes that were never going to arrive.

**Net effect, measured with `make bench`:** a 411-line file went from break-even at 9+ turns to **3+ turns**; a 400KB file went from a 2.6x loss to paying off immediately.

**Tooling added** (`make smoke`, `make bench`, `make check` — see the README). `make smoke` is the real-API test the final review recommended and that had never been written; it passes. `make bench` prices interception in dollars because `skim stats` structurally cannot: it sums input/output/cache-write/cache-read into one integer, but those bill at 1x/5x/2x/0.1x and against a different model than the session.

**Two bugs the new tests caught in the new code**, worth noting as evidence the tests are load-bearing rather than decorative: `detect.Measure` returned `PrefixBytes: 0` instead of `Bytes` when no line cap was requested (violating its own documented contract), and the first cut of the partial-coverage banner reported bytes when the only actionable unit is a line offset.

### Metering batch (2026-09-14)

`skim stats` existed to answer "did this save money" and structurally could not. Fixed:

1. **Cost is recorded per call, in dollars, from the CLI itself.** `worker.Run` now returns a `worker.Usage` carrying input / output / cache-write / cache-read separately plus `CostUSD` taken from the envelope's `total_cost_usd`. It is deliberately *not* derived from a price table compiled into skim — prices change, and the CLI already knows the real number for whatever model and auth mode is in play. The old flat sum survives as `Entry.WorkerTokens`, documented as a size diagnostic that must never be subtracted from a saving. (The four tiers bill at 1x / 5x / 2x / 0.1x; a 1-hour cache write at 2.0x was confirmed against a real call, where 5,509 cache-write tokens billed $0.011018.)

2. **`skim run` records metrics at all.** It previously recorded none — verified by watching `metrics.jsonl` stay at the same line count across a run — so the entire Bash path was invisible: the bash-hook's own entry carries only a timestamp, and the actual saving and worker cost both happen later, inside `skim run`. It now writes a `Run` entry. End-to-end, that row shows ~14,892 tokens saved where the ledger previously showed nothing at all. `Deps.Record` is optional (nil-tolerant) so a caller that only wants the digest need not wire it.

3. **The cache hit rate describes what it claims to.** `Entry.CacheHit` is now `*bool`: nil means "this path has no digest cache", which is true of Grep, Bash and Run. Counting them as misses is what made one Read plus three Bash interceptions report `0 hit / 4 miss (0% hit rate)`. `Aggregate` skips nil entries, and the row is labelled "Read only".

4. **Grep's saving is measured against the real match output.** `origEst` came from `len(sample)`, but `sample` is skim's own prompt input capped at 32KB — so the ledger booked savings for shrinking skim's own prompt rather than the tool result the model would have received. `Deps.Sample` now also returns the uncapped byte length, and that is the baseline. It also sets `Request.Partial` when the sample is a prefix, so the worker knows it is summarising a slice.

**Also fixed, because the batch made it a latent trap:** `RenderRun` never disclosed that the digest summarises only the last 16KB of output (`runner.tailCap`), so `cat`ing a large file through `skim run` was described as if it were the whole thing. The runner now counts the full stream via the ring buffer (no stat, no flush assumption), passes coverage to `RenderRun`, and the `KindRun` prompt says "TAIL ONLY" when it applies. This is the same honesty bug fixed for Read in the previous batch, on the third path.

**`skim stats` rewritten.** It now reports per-tool interceptions / tokens saved / dollars spent, the cache rate over cache-eligible entries only, and a dollar verdict: saving priced at the session model's rate (first read and with re-sends at the 0.1x cached rate) against dollars actually billed. The session model **cannot be detected** — the `PreToolUse` payload does not carry it — so it is an explicit `--session-model` flag (default `opus-5`) with the assumption printed in the output, plus `--turns`. The verdict genuinely flips between Opus and a Haiku session, and there is a test pinning that. Map iteration was also sorted, fixing the non-deterministic ordering noted in the deferred minors.

The fake `claude` stub gained a `total_cost_usd` in its `usage` mode so the cost path is exercisable without a real API call; its contract comment documents it.

### Grep-fidelity batch (2026-09-14)

Started as "skim decides whether to intercept using a different query than the model asked for" and turned up something larger on the way.

**The bigger find: Grep interception was silently dead.** `exec.Command("rg", …)` does a PATH lookup for an *executable*, and a normal Claude Code install has no `rg` executable. On this machine `which rg` printed a **zsh function** that re-execs the Claude Code binary with `argv[0]=rg`, and no `rg` binary existed anywhere on disk — so `rgCount` failed with "executable file not found", the hook degraded open, and Grep interception never ran at all. Safely, invisibly, uselessly: the same shape as the original fence bug. Fixed by resolving ripgrep through a fallback — standalone `rg` first, else the `claude` binary invoked with `argv[0]="rg"`, which reports itself as **ripgrep 14.1.1** and accepts the full ripgrep CLI. skim already requires `claude` for the worker, so this is a strictly weaker dependency than standalone ripgrep. First confirmed working end to end here: a 240-match case-insensitive Grep denied with a cluster digest, where it had always passed through.

**The original two, with the real mechanisms:**

- **Occurrences vs lines.** `rgCount` used `--count-matches` (occurrences) while Grep in content mode returns one line per match, and `grep_max_matches` is compared against that. `foo foo foo\nfoo\nbar` reports **4** with `--count-matches` and **2** with `--count`. Every line containing more than one hit pushed a call toward interception it had not earned. Now `--count`.
- **Dropped flags.** `hookio.GrepInput` parsed only pattern/path/output_mode/glob/type/head_limit. The real payloads were captured from a live session with a throwaway logging hook, which is how the exact (hyphenated) key names were confirmed rather than guessed:

  ```json
  {"pattern":"todo","path":".","output_mode":"content","-i":true,"-A":2}
  {"pattern":"func","path":".","output_mode":"content","-B":1,"head_limit":5}
  {"pattern":"type .* struct","path":".","output_mode":"content","multiline":true}
  ```

  `-i` alone changed a count 1→3 in a direct test. **`multiline` turned out to fail differently than expected**: ripgrep *refuses* a pattern containing a literal `\n` without `--multiline`, exiting 2 with `the literal "\n" is not allowed in a regex`. Since only exit 1 means "no matches", dropping the flag made every multiline Grep an error → degrade open → never intercepted. The test asserts that real behaviour rather than the miscount originally assumed.

  Flags are now split by what they affect: `matchArgs` (glob, type, `-i`, `--multiline`) decides *which lines match* and feeds both passes; `outputArgs` (`-C`, or `-A`/`-B`, and `-n`) only changes *how much text would have been returned* and feeds the sample pass alone, since context lines would inflate a match count. `multiline` is passed without `--multiline-dotall` deliberately: whether Claude Code adds dotall is not observable from the payload, and under-counting is the safe direction — it means passing a call through rather than intercepting one that did not warrant it.

**Extracted `internal/rg`** so `skim doctor` can share the resolution logic. Doctor previously warned "`rg` not found — Grep interception will pass through" on machines where it works fine; it now names the route and **probes** it with `rg.Verify()`. That probe exists because the fallback trusts that a binary called `claude` is Claude Code: testing against a stub `claude` produced a quietly wrong count (a 240-match search counted low enough to pass through), which is safe but invisible. The probe is doctor-only — a process spawn per interception would be waste.

**15 tests in `internal/rg`, all driving the real ripgrep** against fixtures. There were previously **no tests whatsoever** on the rg plumbing, which is why both bugs survived every review: an argument-shape assertion would have passed while skim counted the wrong thing. Two of them (`TestVerify_RejectsAnImpostor`, `TestPath_NoRipgrepAnywhere`) cover the failure modes the fallback introduces.

### Direct-API worker batch (2026-09-17)

The last large cost lever: every nested `claude -p` call paid for Claude Code's own system prompt — 5,509 tokens with `--tools ""`, written to a 1-hour cache and billed at **2x** the input rate, about **$0.011 per cold call** before any file content. On a small file that fixed overhead was most of the bill. `internal/worker` now has two transports and prefers the cheap one.

**The gating constraint, found before any code was written.** A direct API call needs credentials, and this machine has none the Go SDK could see: no `ANTHROPIC_API_KEY`, no `ANTHROPIC_AUTH_TOKEN`, no `ant` CLI, no `~/.config/anthropic` profile. The Claude Code subscription token lives in the **macOS keychain** (`Claude Code-credentials`, holding a `claudeAiOauth` access token). skim deliberately **does not** read it — borrowing a session credential for out-of-band API calls is fragile against refresh and expiry, is a credential-exfiltration pattern regardless of intent, and a subscription is not an API entitlement. So the direct path could never be a straight replacement; it is preferred-when-available with the CLI as fallback, which means **a subscription-only install behaves exactly as it did before**.

**Zero dependencies preserved, by the user's choice.** The official Go SDK works (v1.72.0) but pulls in 5 transitive modules, which would have invalidated the `deps: none` badge and the single-binary claim. Asked, and the answer was raw `net/http`. The wire format was taken from the `claude-api` skill's documented cURL examples and error-code tables rather than guessed: `POST /v1/messages`, `anthropic-version: 2023-06-01`, `x-api-key` for a key or `Authorization: Bearer` **plus** `anthropic-beta: oauth-2025-04-20` for a token, response `.content[]` text blocks, `.usage.*`, and the `{"type":"error","error":{...}}` failure shape. `go.mod` still has no `require` block.

**The request is deliberately minimal** — no `system`, no `thinking` (omitting it means none on Haiku 4.5), no `cache_control`. Each omission is a measured finding from an earlier batch rather than a default.

**Other differences worth knowing:**
- **Cost accounting regressed slightly, on purpose.** The Messages API reports tokens but not money; `total_cost_usd` is a CLI convenience. So the direct transport prices its own calls from a narrow `workerPrices` table. The CLI figure is authoritative and survives price changes; this one can go stale. An unknown model records **0** rather than a guess, which `skim stats` already surfaces as "n of m calls reported cost".
- **No retries.** A retry inside a PreToolUse hook spends the latency budget twice on what is only an optimisation. The HTTP status and error type are folded into the error so a 429 or 529 is recognisable in `skim.log`.
- **`stop_reason: "max_tokens"` is named explicitly.** Truncation and malformation both present as an unparseable digest, but only one is fixed by raising `maxOutputTokens` (4096; real digests measured 353–1,339 output tokens).
- `skim doctor` now prints which transport is active, because the two differ by ~5.5K tokens per interception and nothing else surfaced it.

**⚠️ The direct transport has never been exercised against the real API.** There is no API key on this machine, so it is covered only by unit tests against an `httptest` server: 19 assertions including both auth header shapes, fence stripping, split text blocks, error statuses, the truncation case, and `errors.Is(err, ErrTimeout)` parity with the CLI path. **That is exactly the gap that produced the fence bug** — the entire fake-`claude` suite was green while the product silently did nothing in production. `make smoke` now prints which transport it exercised and warns when the direct path is uncovered. **Before trusting the direct path, set `ANTHROPIC_API_KEY` and run `make smoke`.** Highest-value single action left on this branch.

A deadlock was also fixed in the new tests: a handler parked on `r.Context().Done()` deadlocks `httptest.Server.Close()`, which waits for outstanding handlers. The handler is now released by the test.

### Still open (after five batches)

Ranked, with the reasoning recorded so the next session does not re-derive it:

- **The Bash/Run baseline is an upper bound.** `Run`'s `OrigTokensEst` is everything the command emitted, but Claude Code's Bash tool truncates very long output by an amount skim does not model, so for enormous output the recorded saving overstates the true counterfactual. This is the same class of error that the 2000-line Read cap fixed; it needs the Bash tool's actual truncation limit, which is not documented in the tool contract the way Read's 2000 lines is. Far better than the previous state (no measurement at all), but not exact.
- **The CLI transport still carries the ~5.5K-token system prompt**, and it is the transport every subscription install uses. The direct path removes it but needs an API key. `--system-prompt` would cut the CLI's to ~1.3K and is untried; `--bare` cuts more but reads auth strictly from `ANTHROPIC_API_KEY`, so it cannot help the very users stuck on the CLI.
- **Validate the direct transport against the real API** (set `ANTHROPIC_API_KEY`, run `make smoke`). It is unit-tested only. See the batch note above for why that specific gap is the one this project has already been burned by.
- **Smaller:** `detect.Measure` still walks whole files when `os.Stat` would settle the byte threshold; `cache.Sweep` runs on every single hook invocation; the README's kill-switch bullet claims `Validate()` rejects "a model this CLI cannot run" when it only checks non-empty.

### Worth your attention (superseded by the batch above — kept for the trail)

The fix wave's live smoke test on a 3191-line/92423-byte real file reported: **saved ~22,556 tokens, worker spent ~86,905 tokens, net ~−64,349**. The worker cost *exceeded* the digest savings on this one file. This isn't necessarily a net loss (Haiku tokens are far cheaper than whatever drives the main session), but it's exactly the signal spec §9 designed `skim stats` to surface, and it's now measurable for the first time (I6 fixed it). **Recommended follow-up once on GitHub:** run `skim stats` against a real multi-day session and consider raising `read_max_lines`/`read_max_bytes` if the worker-cost side dominates — the current defaults (300 lines / 60KB) may be too aggressive for Haiku's actual summarization cost on typical files.

### Why static badges, and the blocker on publishing

**The repo is private.** Two consequences that drove the design:

1. **Dynamic shields.io badges cannot work.** Anything that reads repo data — stars, last-commit, license, release, CI status — requires shields.io to see the repo, so on a private repo those render as "repo not found"/"invalid". Only static `img.shields.io/badge/...` badges were used, and they work either way. There is also deliberately **no CI badge**, because this repo has no CI workflow — a green badge with nothing behind it would be a lie.
2. **GitHub Pages on a private repo requires a paid plan** (Pro/Team/Enterprise). On GitHub Free, Pages only publishes from public repos. `gh api repos/init-kaushal/skim/pages` currently 404s (no site configured). So publishing needs either making the repo public or a plan that supports private Pages.

Also noted while checking: **the repo has no LICENSE file** (`licenseInfo: null`). That's worth deciding before making anything public, and it's why there's no license badge.

## Deferred minors (not blocking, real follow-up value — from every task's review + the final review)

Grouped by area, for whenever someone circles back to polish:

- **config:** no test for the malformed-JSON→`Default()` fallback path.
- **detect:** `regexp.MustCompile` in `globToRegexp` could use a comment on why it's panic-safe; `FileSize` reads the whole file even after both thresholds are already exceeded (could early-exit); `**/` in glob patterns compiles to `.*` rather than `(.*/)?`, so `**/go.mod` also matches e.g. `/x/cargo.mod` — harmless with the shipped defaults, surprising for user-supplied globs.
- **worker:** timeout error message can misattribute the configured duration when a shorter parent context deadline actually fired; no `cmd.WaitDelay` hardening against a hypothetical hung child; a parent-context `Canceled` produces an uninformative bare error; no `\r\n` handling in the fence-strip (only `\n`); a narrow theoretical edge case where a malformed response with no real closing fence and stray trailing backticks in a JSON string could be mis-stripped (requires an already-broken response).
- **cache:** `Sweep` silently ignores individual `os.Remove` failures (best-effort by design).
- **handler:** degrade-open test coverage is uneven across branches (only the worker-error branch is directly tested per hook; `ParseFileMap`-error/`CacheKey`-error/`readCapped`-error/cache-hit-skips-worker aren't each individually tested, though they're structurally identical one-liners); a local variable named `max` shadows the Go 1.21 builtin in `read.go`; several tests discard `os.WriteFile`'s error return.
- **runner:** `Deps.Now` field is unused (kept for interface stability per spec); `os.MkdirAll`/`os.Create` errors aren't wrapped with context; coverage gaps on `argv==0`, the `ParseRun`-error fallback path, and ring-buffer trimming under a write larger than the 16KB cap; an empty `.log` file is created even if the child process fails to start.
- **cli:** `Stats`'s per-tool output iterates a Go map (non-deterministic ordering — sort the keys); `Doctor`'s `defer f.Close()` inside an `if` block defers to function return rather than block exit (harmless here); `Config`'s pretty-print swallows a `json.MarshalIndent` error (can't actually fail for this struct); `clearCache` under-counts silently on a permission failure; thin test coverage on `--clear-cache`, `set model`, `set disabled`, the Doctor INACTIVE line, and "rg missing still exits 0".

## How this was built (for anyone curious about process, not just code)

This was built via `superpowers:brainstorming` → `superpowers:writing-plans` → `superpowers:subagent-driven-development`: a controller session dispatched a fresh implementer subagent per task (mostly Haiku for mechanical transcription tasks, Sonnet for multi-file orchestration/integration tasks, Opus for the whole-branch reviews and the final fix wave), with a task-scoped spec+quality review after every task and a broad whole-branch review at the end. Two implementer subagents hit session rate-limits mid-task (Task 14's wiring, and the final fix wave) and were resumed rather than restarted — their in-progress work was inspected read-only first (build/vet/test) before resuming, and both turned out to be functionally complete, just uncommitted.

The single most valuable moment in the whole process was a manual, real-API smoke test (not a unit test) that caught the fence-wrapping bug — the entire fake-`claude`-based test suite was green while the product silently did nothing against the real model. The final review's own recommendation (Recommendation #3 in its report, referenced above) was to institutionalize this as a `make smoke` target gated on a real API key, run before every release. That target does not exist yet — worth adding.
